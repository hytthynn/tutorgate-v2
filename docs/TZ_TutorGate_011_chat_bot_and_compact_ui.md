# ТЗ: TutorGate — пакет 011

Дата фиксации: 06.09.2026  
Статус: реализовано в коде пакета 011.

## 1. Цель пакета

Пакет 011 закрывает четыре связанные задачи:

1. исправить внутреннее значение `__historical__` в форме занятия и корректно показывать пустые списки учеников/предметов;
2. сделать строки в разделах учеников и репетиторов компактнее;
3. добавить веб-чат репетитора с учеником, где репетитор пишет на сайте, а ученик отвечает через Telegram;
4. превратить Telegram-бот в полноценную точку входа: `/start`, inline-меню, inline-ссылки регистрации/восстановления, выбор репетитора для ученика и уведомления репетитору.

Зафиксированные продуктовые решения:

- чат один на пару `ученик ↔ репетитор`, а не на предмет;
- веб-чат пакета 011 доступен активной системной роли `tutor`; admin-аккаунт не подставляется в Telegram picker ученика даже если используется как преподаватель в расписании;
- только текстовые сообщения;
- максимум 4000 символов;
- репетитор пишет ученику только на сайте TutorGate;
- ученик отвечает через Telegram;
- у репетитора есть непрочитанные сообщения, счётчики, время, разделители по датам и автоматическая прокрутка;
- Telegram-меню репетитора и администратора содержит только `🌐 Открыть TutorGate`;
- Telegram-меню ученика содержит `🌐 Открыть TutorGate` и `💬 Написать репетитору`;
- кнопки «Ответить» в Telegram-уведомлении репетитора нет.

## 2. TG-011-01 — форма занятия

### 2.1. Внутренний sentinel

`__historical__` остаётся внутренним значением формы для сохранённого исторического предмета, но никогда не отображается пользователю.

Для нового занятия с draft и `subjectId = null` select должен оставаться в пустом состоянии, если `subjectChanged = true`. Историческое значение допустимо только при редактировании существующего исторического занятия, когда предмет уже удалён/недоступен и пользователь его не менял.

### 2.2. Пустые списки

Поле «Ученик»:

- обычное состояние: `Выберите ученика`;
- если учеников нет: `Нет доступных учеников`;
- поле блокируется для нового занятия, если выбирать не из чего.

Поле «Предмет»:

- до выбора ученика: `Сначала выберите ученика`;
- обычное состояние после выбора ученика: `Выберите предмет`;
- если предметов нет вообще или для выбранного ученика нет доступных назначений: `Нет доступных предметов`;
- поле блокируется, если предмет выбрать невозможно.

Кнопка добавления нового занятия недоступна, пока нет выбранного ученика и хотя бы одного доступного ему предмета.

### 2.3. Acceptance criteria

- `__historical__` не виден в UI;
- новый draft с пустым subject не показывает служебное значение;
- пустой список учеников явно подписан;
- пустой список предметов явно подписан;
- существующее историческое занятие по-прежнему открывается и сохраняется без потери snapshot-названия предмета.

## 4. TG-011-03 — чат репетитор ↔ ученик

### 4.1. Маршрут и навигация

Добавляется маршрут:

`/tutor/chats`

В навигацию репетитора добавляется пункт `Чаты` со счётчиком непрочитанных сообщений. Счётчик обновляется периодически без ручной перезагрузки страницы.

### 4.2. Модель диалога

Один диалог соответствует уникальной паре:

`student_id + tutor_id`

Диалог доступен только пока между пользователями существует хотя бы одно активное `student_tutor_assignments`. Разные предметы не создают отдельные чаты.
Получатель должен иметь активную системную роль `tutor`; admin-аккаунты не участвуют в Telegram chat picker этого пакета.

### 4.3. Веб-интерфейс репетитора

Экран состоит из:

- списка назначенных учеников;
- последнего сообщения и unread badge в списке;
- области истории;
- имени выбранного ученика;
- разделителей `Сегодня`, `Вчера` или даты;
- времени каждого сообщения;
- визуального разделения сообщений ученика и репетитора;
- статуса `Не доставлено в Telegram` для сообщения репетитора при ошибке Bot API;
- textarea до 4000 символов;
- счётчика символов;
- отправки Enter, перенос строки через Shift+Enter;
- автопрокрутки к последнему сообщению.

Клиент опрашивает сервер примерно раз в 5 секунд, пока вкладка активна. Открытый диалог помечается прочитанным только до реально полученного последнего message id, чтобы конкурентно пришедшее новое сообщение не было ошибочно погашено.

В первой версии UI показывает последние 200 сообщений диалога и явно сообщает об этом, если история длиннее.

### 4.4. Доставка сообщения репетитора

Последовательность:

1. Server Action повторно проверяет `requireRole("tutor")`;
2. SQL RPC проверяет активное назначение пары;
3. сообщение атомарно записывается в БД со статусом `pending`;
4. server-only слой получает Telegram chat ID ученика — идентификатор не возвращается браузеру;
5. Bot API доставляет текст ученику;
6. статус становится `sent` или `failed`;
7. Telegram message id успешной доставки сохраняется в private mapping, чтобы ответ Telegram через Reply однозначно определял диалог.

### 4.5. Ответ ученика из Telegram

Ученик может написать двумя способами:

1. нажать `💬 Написать репетитору`, выбрать репетитора при необходимости и отправить следующий текст;
2. использовать стандартный Telegram Reply на сообщение, которое пришло от репетитора через TutorGate.

Reply имеет приоритет над сохранённым выбором получателя. Если назначение уже снято, сообщение не записывается в чат.

Для повторных webhook delivery используется `telegram_update_id`: один Telegram update не может создать два одинаковых chat message.

### 4.6. Непрочитанные

Непрочитанным считается сообщение ученика новее `tutor_last_read_at` соответствующего conversation. В sidebar показывается суммарное количество непрочитанных сообщений по активным назначениям.

### 4.7. Telegram-уведомление репетитору

После нового сообщения ученика репетитор получает Telegram-уведомление с preview и единственной кнопкой:

`💬 Открыть чат`

Для обычного tutor кнопка ведёт прямо на `/tutor/chats?student=<uuid>`.

Репетитор не может отправлять ответ через бота: любой обычный текст репетитора в боте возвращает переход на веб-чат.

### 4.8. Безопасность

- Telegram IDs/chat IDs не раскрываются браузеру;
- service key только в server-only слоях;
- authenticated chat RPC проверяют `auth.uid`, активный account и назначение;
- RLS чтения chat tables требует участия пользователя и существующего назначения;
- private Telegram state, update dedupe и reply mapping закрыты от `anon/authenticated`;
- текст ограничен 4000 символами в UI и БД;
- вложения первой версией не принимаются.

## 5. TG-011-04 — Telegram bot

### 5.1. Webhook

Webhook принимает:

- `message`;
- `callback_query`.

`setWebhook` настраивает `allowed_updates = ["message", "callback_query"]`.

Также `setMyCommands` регистрирует:

`/start — Открыть меню TutorGate`

### 5.2. `/start`

Обычный `/start` определяет связанный активный профиль по постоянной паре Telegram user/chat ID и показывает role-aware inline keyboard.

Deep-link `/start <token>` сохраняет существующий application confirmation flow и имеет приоритет над обычным меню.

### 5.3. Inline-ссылки

В теле Telegram-сообщения больше не выводятся raw URL для:

- регистрации;
- повторной регистрации;
- восстановления пароля.

Они передаются только в `url` inline-кнопок.

`supabase/migrations/202609060011_chat_and_telegram_bot.sql`

## 8. Тестирование

Добавить регрессии:

- шаблоны `/start` и inline-кнопок;
- регистрационный/reset URL отсутствует в тексте и находится в inline keyboard;
- `__historical__` не становится default для нового draft;
- пустые состояния select;
- наличие chat navigation/unread/polling;
- применение migration 011 на полном наборе миграций;
- active assignment требуется для send/read;
- Telegram Reply попадает в тот же conversation;
- повтор одного `telegram_update_id` не создаёт второе сообщение;
- снятие назначения блокирует дальнейшую отправку;
- private Telegram mapping недоступен authenticated.

Production Telegram/Supabase не должны использоваться в локальных fixture-тестах.

## 9. Release / deployment

Порядок:

1. backup/staging;
2. применить migration 011 после 010;
3. развернуть application code того же пакета;
4. повторно выполнить `npm run telegram:webhook`, чтобы Telegram начал присылать `callback_query` и обновилась команда `/start`;
5. smoke test двух реальных Telegram аккаунтов: tutor + student;
6. проверить регистрацию и password reset через inline-кнопки;
7. проверить снятие назначения во время активного chat state.

Старый webhook после появления inline-кнопок не следует оставлять в production: без `callback_query` кнопка `Написать репетитору` не сможет отработать.

## 10. Definition of Done

Пакет готов, когда:

- форма занятия не показывает `__historical__` и корректно сообщает об отсутствии данных;
- directory rows заметно компактнее на desktop и mobile;
