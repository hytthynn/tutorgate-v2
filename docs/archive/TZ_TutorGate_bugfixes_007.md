# ТЗ: TutorGate — пакет UI/UX багфиксов

**Дата:** 05.09.2026  
**Проект:** TutorGate v2  
**Источник:** анализ архива `tutorgate-v2(2).zip`, присланных скриншотов и уточнений заказчика.  
**Статус:** согласовано к реализации.

---

## 1. Цель

Исправить набор UX-багов расписания, фильтров, селектов и форм, унифицировать состояния загрузки/сохранения и привести Markdown-документацию проекта в актуальное состояние без дублирования и устаревшего мусора.

Главный принцип релиза: **не менять существующие бизнес-правила расписания и безопасность БД**, если это не требуется данным ТЗ. Серверный SQL-magnet, RLS, owner-checks, rollover и текущие RPC должны остаться источником истины.

---

## 2. Подтверждённые решения заказчика

1. Drag&drop использует **локальный визуальный магнит по видимым занятиям**. Сервер остаётся финальным арбитром и может дополнительно сдвинуть занятие из-за скрытого конфликта ученика.
2. У карточки занятия убрать только пустое место, которое сейчас занимает невидимая иконка `CircleCheck`. Внутренний padding карточки оставить.
3. Tooltip у кнопки «Добавить занятие»:
   - текущая неделя — **без tooltip**;
   - прошлая неделя — tooltip «Добавлять занятия можно только в текущей неделе.»;
   - будущая неделя — tooltip о том, что занятия появятся автоматически.
4. Статус сохранения расписания отображать **постоянно**.
5. Поиск по ФИО — debounce **300 мс**; URL обновлять через `router.replace`. Остальные фильтры применять сразу.
6. Поиск убрать **из всех выпадающих списков с предметами**. Поиск по ученикам/репетиторам оставить.
7. Loading унифицировать на всех согласованных кнопках, которые отправляют/изменяют данные.
8. В кабинете ученика, раздел «Репетиторы», **полностью убрать строку «Администратор · Репетитор»** под именем администратора. Это не относится к роли пользователя в sidebar.
9. Устаревшие Markdown-файлы разрешено удалять/переносить в архив; актуальную документацию сделать компактной и непротиворечивой.

### 3.1. Найденные причины текущих багов

#### Drag&drop

В `calendar.tsx` функция `showPreview()` сейчас только округляет позицию по сетке 5 минут через `snapMinutes()`. Уже существующая функция `nearestFreeStart()` из `src/features/schedule/time.ts` при preview **не используется**.

При этом серверный resolver в `supabase/migrations/202609050006_schedule_upgrade.sql` уже корректно ищет ближайший полный свободный интервал с учётом конфликтов tutor + student.

Следствие: во время drag карточка визуально может лежать поверх другой, а реальный magnet срабатывает только после отпускания мыши и ответа сервера.

#### Пустой отступ возле имени

В `calendar.tsx` `CircleCheck` рендерится всегда, а у непройденного занятия скрывается через:

```tsx
style={{ visibility: lesson.completed ? "visible" : "hidden" }}
```

Из-за `width: 14px`, `flex-basis: 14px` и `gap: 3px` невидимая иконка продолжает занимать место.

#### Tooltip «Добавить занятие»

В `toolbar.tsx` кнопка всегда обёрнута в `Tooltip`, включая активную кнопку текущей недели. Поэтому появляется лишняя подсказка «Добавить занятие».

#### Статус сохранения

В `calendar.tsx` сейчас:

```tsx
pending ? "Сохранение…" : "Все 24 часа"
```

То есть idle-состояние не является статусом сохранения. Кроме того, pending создания/редактирования из `LessonDialog` не полностью связан с этим индикатором.

#### Фильтры

- `PeoplePage`: GET-форма + кнопка «Найти».
- `StatisticsView`: форма + кнопка «Применить».

Фильтры не применяются автоматически.

#### Предметные select

`searchable` сейчас используется, в частности, в:

- выборе предмета занятия;
- выборе предмета в назначении ученика;
- фильтре по предмету в списке репетиторов.

#### Роль администратора в кабинете ученика

В `PeoplePage` строка:

```tsx
{p.role === "admin" && <small>Администратор · Репетитор</small>}
```

рендерится независимо от роли текущего зрителя, поэтому её видит ученик.

#### Markdown

Обнаружено:

- крупное старое ТЗ `docs/TZ_TutorGate_schedule_bugfixes.md` (~1250 строк);
- одинаковые правила schedule upgrade 006 продублированы в `README.md`, `AGENTS.md`, `docs/architecture.md`, `docs/progress.md`;
- `README.md` ссылается на отсутствующие `TutorGate_MVP_TZ.md` и `TutorGate_Schedule_TZ.md`;
- `START_HERE.md`, `upgrade-006.md`, `verification.md`, `progress.md` привязаны к предыдущей ревизии и частично дублируют друг друга.

# 4. Функциональные требования

## FR-01. Визуальный magnet при drag&drop занятия

### Проблема

Во время перетаскивания preview карточки может визуально пересекаться с другим занятием. Сервер исправляет позицию только после drop.

### Требуемое поведение

Во время перемещения карточка должна сразу отображаться на ближайшем свободном месте по тем занятиям, которые доступны текущему расписанию на клиенте.

### Правила magnet

Сохранить уже существующие правила `nearestFreeStart()`:

- шаг сетки: 5 минут;
- учитывается **полная длительность** переносимого занятия;
- исходное переносимое занятие исключается из busy-интервалов;
- выбирается ближайший свободный старт;
- при одинаковом расстоянии выбирается **более поздний** вариант;
- старт остаётся внутри выбранного локального дня;
- максимальный старт — `23:55`;
- окончание может перейти через полночь;
- учитываются занятия, пересекающие границу суток.

### Реализация

В `src/components/schedule/calendar.tsx`:

1. Импортировать `nearestFreeStart` из `@/features/schedule/time`.
2. В `showPreview()` сначала вычислять желаемый `desiredStart` по координатам указателя.
3. Сформировать `busy` из текущего массива `lessons`, исключив `g.source.id`.
4. Перед созданием preview вызывать:

```ts
nearestFreeStart(desiredStart, source.durationMinutes, offset, busy)
```

5. В `g.target` записывать именно найденный локальным magnet старт.
6. Preview строить по найденному старту, а не по необработанному указателю.

### Важное ограничение безопасности

Клиентский magnet **не должен пытаться получать скрытые занятия ученика у другого репетитора**.

Причина: серверный SQL resolver специально видит скрытые student-конфликты без раскрытия их данных. Это поведение сохраняется.

Итоговый flow:

1. drag → локальный magnet по видимому расписанию;
2. drop → `moveLessonAction()`;
3. SQL resolver повторно проверяет tutor + student конфликты;
4. если существует скрытый конфликт, сервер может вернуть другую позицию;
5. UI принимает `result.lesson` как каноническую позицию и оставляет существующий информационный toast о сдвиге.

### Если на выбранном дне нет свободного интервала

- preview **не должен накладываться** поверх существующего занятия;
- `g.target` сбрасывается;
- визуально карточка остаётся/возвращается на последнюю валидную позицию либо исходную позицию;
- drop не выполняет мутацию;
- после отпускания показать один toast:
  - `В выбранном дне нет свободного интервала для этого занятия.`

Не показывать toast на каждом `pointermove`.

### Не менять

- SQL resolver;
- RLS;
- exclusion constraints;
- правила будущей недели;
- серверный повторный magnet.

### Acceptance criteria

- [ ] При drag на занятое время preview до `pointerup` автоматически смещается на ближайший свободный интервал.
- [ ] Preview ни в одном валидном состоянии не лежит поверх другого видимого занятия текущего tutor.
- [ ] Drag по свободному времени сохраняет обычный snap 5 минут.
- [ ] Собственная исходная карточка не считается конфликтом сама с собой.
- [ ] При равном расстоянии preview выбирает более позднее время.
- [ ] Cross-midnight занятия корректно блокируют пересечение.
- [ ] Сервер всё ещё может дополнительно сместить карточку из-за скрытого student-конфликта.
- [ ] После серверного сдвига UI показывает фактическую позицию из `result.lesson`.
- [ ] Drag в будущую неделю по-прежнему запрещён.

## FR-02. Убрать пустой отступ возле имени занятия

### Требуемое поведение

У непройденного занятия имя должно начинаться без пустого пространства от невидимой галочки.

Внутренний горизонтальный padding самой карточки `padding: 0 4px` **оставить**.

### Реализация

Вместо постоянно присутствующей скрытой иконки рендерить `CircleCheck` только для `lesson.completed === true`.

Пример ожидаемого подхода:

```tsx
<strong>
  {lesson.completed && (
    <CircleCheck
      className="lesson-check"
      aria-hidden="true"
      data-testid="lesson-completed"
    />
  )}
  {segment.continuation ? "↳ " : ""}
  {name}
</strong>
```

Удалить `visibility: hidden` для непройденного состояния.

### Acceptance criteria

- [ ] У обычного занятия отсутствует 14px пустое место перед именем.
- [ ] Padding карточки остаётся визуально таким же, как сейчас.
- [ ] У проведённого занятия зелёная `CircleCheck` отображается как раньше.
- [ ] Продолжение занятия `↳` корректно выравнивается и без галочки, и с галочкой.

## FR-04. Постоянный красивый статус сохранения расписания

### Цель

Пользователь всегда должен понимать, сохранены ли последние изменения расписания.

### Состояния

Ввести отдельное состояние, например:

```ts
type SaveState = "saving" | "saved" | "error";
```

#### `saving`

- `Loader2` с `spin`;
- текст `Сохранение…`;
- `aria-live="polite"` / `role="status"`.

#### `saved`

- аккуратная `Check` / `CircleCheck`;
- текст `Сохранено`;
- статус остаётся видимым постоянно.

#### `error`

- `CircleAlert` / аналогичная иконка;
- текст `Не сохранено`;
- статус остаётся до следующего успешного сохранения;
- существующий toast ошибки также остаётся.

### Начальное состояние

После успешной загрузки расписания — `saved`.

### Какие операции обязаны менять статус

- drag/move занятия;
- создание занятия;
- редактирование занятия;
- удаление одного/нескольких занятий;
- изменение цвета;
- «Проведено» / снятие отметки;
- изменение сдвига МСК.

### Поведение

Перед server mutation:

```text
saved/error → saving
```

После успешного ответа:

```text
saving → saved
```

После network/server error:

```text
saving → error
```

Локальная ошибка валидации формы до отправки запроса не должна переводить глобальный статус в `error`.

### Интеграция `LessonDialog`

Сейчас `LessonDialog` сообщает наружу только `onPending`. Нужно передать в календарь успешный/ошибочный результат сохранения, например через:

```ts
onSaveState?: (state: SaveState) => void
```

или эквивалентный callback-контракт.

Не оставлять создание/редактирование занятия вне общего save status.

### UI

Заменить `Все 24 часа` в `.schedule-save-status` на новый статус.

Стиль:

- компактный;
- без большого badge;
- соответствует существующей warm mocha теме;
- `saved` — спокойный зелёный акцент;
- `saving` — текущий muted/accent;
- `error` — существующий danger tone.

### Acceptance criteria

- [ ] После открытия расписания отображается `Сохранено`.
- [ ] На время каждой перечисленной мутации отображается `Сохранение…` со spinner.
- [ ] После успеха снова постоянно отображается `Сохранено`.
- [ ] После ошибки постоянно отображается `Не сохранено` до следующего успешного изменения.
- [ ] Создание и редактирование из `LessonDialog` входят в тот же status flow.
- [ ] Текст `Все 24 часа` больше не используется как save status.

## FR-05. Автоматические фильтры без кнопок «Найти» / «Применить»

# FR-05.1. Репетиторы и ученики

### Требование

В admin-разделах:

- `/admin/tutors`
- `/admin/students`

убрать кнопку `Найти`.

Фильтры должны автоматически менять query string и обновлять серверные результаты.

### Поиск по ФИО

- debounce: **300 мс**;
- после 300 мс без нового ввода вызвать `router.replace()`;
- пустую строку удалять из query string;
- `Enter` не должен быть необходим для применения;
- не создавать отдельную browser-history запись на каждую букву.

### Select-фильтры

- предмет в `/admin/tutors` — применять сразу;
- репетитор в `/admin/students` — применять сразу;
- пустое значение удаляет соответствующий query param.

### Архитектура

`PeoplePage` оставить Server Component для получения и фильтрации данных.

Вынести панель фильтров в Client Component, например:

```text
src/components/people/directory-filters.tsx
```

Client Component получает:

- `kind`;
- начальный `q`;
- текущий filter value;
- список subject/tutor options.

Использовать:

- `useRouter()`;
- `usePathname()`;
- `useSearchParams()` либо единый локальный state;
- `useTransition()` для состояния навигации.

### Обязательное требование против race condition

Debounce поиска и мгновенное изменение select не должны перетирать значения друг друга.

URL всегда должен строиться из **полного актуального состояния фильтров**, а не из устаревшего closure.

Пример нежелательного бага:

1. пользователь вводит имя;
2. до истечения 300 мс меняет предмет;
3. subject обновляется;
4. старый debounce перезаписывает URL и удаляет subject.

Такого поведения быть не должно.

### UX загрузки

Пока RSC-результаты обновляются:

- можно использовать существующий `loading-dim` / `aria-busy` для списка;
- не блокировать ввод в search без необходимости;
- не возвращать кнопку `Найти` в качестве индикатора.

# FR-05.2. Статистика

### Требование

В:

- `/admin/statistics`
- `/tutor/statistics`

полностью убрать кнопку `Применить`.

Изменения контролов применяются автоматически через `router.replace()`.

### Что обновляется сразу

- период 7 / 14 / 30 дней;
- «Свой период»;
- выбранный tutor в admin statistics;
- metric: заработок / часы / занятия;
- `Дата от` и `Дата до`, когда пара дат валидна.

### Свой период

При выборе `custom`:

- сразу показать date inputs;
- использовать текущие `data.query.from` / `data.query.to` как валидные начальные значения;
- сформировать валидный URL `period=custom&from=...&to=...`.

При редактировании дат:

- не отправлять заведомо невалидный запрос, если одна дата временно пустая;
- не применять пару, если `from > to`;
- после получения валидной пары применить её сразу;
- пользователь не должен нажимать отдельную кнопку.

### URL

Для не-custom периода удалить `from` и `to` из URL как ненужные параметры.

Не использовать `router.push()` для каждого изменения фильтра; использовать `router.replace()`.

### Pending UI

Сохранить `useTransition()` и `aria-busy`.

Chart/KPI могут использовать существующее `loading-dim` во время перехода.

### Acceptance criteria FR-05

- [ ] В people-разделах нет кнопки `Найти`.
- [ ] Поиск по ФИО обновляет выдачу через 300 мс после остановки ввода.
- [ ] Select-фильтр обновляет выдачу сразу.
- [ ] Изменение поиска и select подряд не теряет ни один фильтр.
- [ ] В статистике нет кнопки `Применить`.
- [ ] Period/tutor/metric применяются сразу.
- [ ] Валидные custom dates применяются без отдельной кнопки.
- [ ] Все фильтры используют `router.replace`.
- [ ] Browser Back не проходит через каждую введённую букву поиска.

## FR-06. Убрать поиск из всех dropdown с предметами

### Требование

### Обязательные места

#### 1. Добавление/редактирование занятия

`src/components/schedule/lesson-dialog.tsx`

Было:


## FR-07. Единый loading на кнопках, изменяющих/отправляющих данные

### Цель

Любая согласованная data-action кнопка после клика должна явно показывать, что запрос выполняется, и защищать от повторной отправки.

### Общий UI-контракт

Для loading-состояния:

- `Loader2`;
- класс `spin`;
- `disabled`;
- `aria-busy="true"`;
- spinner находится перед текстом либо заменяет иконку в icon-only кнопке;
- повторный submit невозможен;
- по возможности ширина кнопки не должна резко прыгать.

### Рекомендуемая реализация

Расширить `src/components/ui/button.tsx` единым API, например:

```ts
loading?: boolean;
loadingText?: ReactNode;
```

Поведение:

- `disabled={disabled || loading}`;
- при `loading` рендерить `Loader2`;
- если `loadingText` задан — заменить обычный content на spinner + `loadingText`;
- для icon-only кнопки допустим только spinner с сохранением `aria-label`.

`asChild` используется для навигации и не должен получать `loading=true`.

Допустим отдельный `LoadingButton`, если он используется единообразно во всех перечисленных местах.

### Обязательный scope

#### Расписание

`LessonDialog`:

- создание: `Добавить` → `Добавляем…` + spinner;
- редактирование: `Сохранить` → `Сохраняем…` + spinner.

#### Предметы репетитора

`TutorSubjectsDialog`:

- `Сохранить изменения` → `Сохраняем…` + spinner.

#### Назначение репетитора ученику

`AssignmentDialog`:

- `Назначить репетитора` → `Назначаем…` + spinner;
- стрелку во время loading скрыть/заменить spinner.

#### Снятие назначения

`RemoveAssignment`:

- icon `X` на время запроса заменить spinner;
- сохранить доступный `aria-label`, например `Снятие назначения…`.

#### Ставка

`RateForm`:

- уже имеющийся spinner привести к общему компоненту/контракту;
- текст во время запроса: `Сохраняем…`.

#### Добавление предмета

`AddSubjectForm`:

- `Добавить` → `Добавляем…` + spinner.

#### Удаление предмета

`RemoveSubject` confirm:

- `Удалить предмет` → `Удаляем…` + spinner.

#### Заявка

`ApplicationForm`:

- существующий spinner сохранить, привести к общему loading API;
- `Подать заявку` → `Отправляем…`.

#### Авторизация

`AuthForm`:

- login → `Входим…`;
- register → `Создаём аккаунт…`;
- forgot → `Отправляем…`;
- reset → `Сохраняем…`;
- во всех случаях spinner.

#### Выход

`Navigation` logout button:

- после submit заменить `LogOut` на spinner;
- кнопка disabled до завершения навигации/action.

Для logout удобно использовать маленький дочерний компонент с `useFormStatus()` внутри `<form>`.

### Вне этого подпункта

Не добавлять spinner к обычным навигационным кнопкам:

- предыдущая/следующая неделя;
- `Текущая`;
- открытие dialogs;
- ссылки;
- `Отмена`.

Глобальный save status расписания из FR-04 остаётся главным feedback для быстрых schedule context actions.

### Acceptance criteria

- [ ] Все перечисленные data-action кнопки показывают spinner во время запроса.
- [ ] Нельзя отправить один action повторно двойным кликом.
- [ ] Icon-only actions не теряют accessible name.
- [ ] Ошибка возвращает кнопку в обычное состояние.
- [ ] Успешная навигация/logout не оставляет застывший spinner.

# 11. Критичные regression-сценарии перед релизом

1. Tutor переносит занятие на другое своё занятие → preview магнитится до drop → save проходит.
2. Tutor переносит занятие на скрытый student-conflict другого tutor → локальный preview допустим → сервер дополнительно сдвигает → чужие данные не раскрываются.
3. Drag на future week → отказ, исходное занятие не меняется.
4. Создание занятия → spinner на кнопке → global `Сохранение…` → `Сохранено`.
5. Ошибка создания/переноса → UI не остаётся в optimistic неверном состоянии → `Не сохранено` + toast.
6. Student открывает `/student/tutors` → admin-tutor отображается без строки роли.
7. Admin вводит ФИО и тут же меняет subject → оба фильтра сохраняются.
8. Statistics filter меняется без `Применить` и не создаёт лишнюю историю browser Back.
9. В предметных dropdown нет search input, но tutor/student combobox остаётся searchable.
10. Все destructive/create/save кнопки блокируют двойной submit и показывают spinner.
