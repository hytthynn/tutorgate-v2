# LaTeX в браузере

С пакета 021 установка Docker/TeX и отдельный сервер компиляции **не требуются**. Код рисунков обрабатывается на устройстве пользователя. Старый HTTP-компилятор и переменные LATEX_RENDER_URL/TOKEN больше не используются. Поле «Преамбула и команды» убрано.

## Что работает

- Формулы, матрицы, array, простые tabular/longtable, команды и русский/английский текст внутри `\text{…}` — через существующий KaTeX. Табличные top/mid/bottomrule переводятся в hline; сложные TeX-таблицы и все CTAN-пакеты не поддерживаются.
- TikZ — настоящий локальный TikZJax WebAssembly в отдельном Web Worker. Установленный TeX не нужен: подготовленный снимок движка поставляется как статический ресурс сайта. Набор пакетов ограничен этим снимком; произвольная установка пакетов и полный PGFPlots не обещаются. Неподдерживаемый код возвращает ошибку.
- Asymptote — ограниченный браузерный 2D-интерпретатор: size, pair/real/int, draw/fill/filldraw, dot, label с обычным текстом, unitsquare/unitcircle/circle, прямые пути `--` и cycle; базовые цвета, linewidth, dashed, Arrow. Поддерживаются арифметика, pi, sqrt/sin/cos/tan/abs. Нет import, программирования, 3D, кривых `..`, произвольных библиотек и TeX-подписей в label. Неподдерживаемая команда отклоняет весь рисунок, а не пропускается молча.
- Администратор может загрузить `.sty` с newcommand/renewcommand/providecommand. Произвольные программы пакетов не исполняются. Старые `.asy`-файлы можно удалить из списка; они не используются как библиотеки браузерного интерпретатора. Изменение собственной команды сохраняется через проверенный admin Server Action и прежний RPC 020.

В отдельном блоке сообщения используйте `\begin{tikzpicture}…\end{tikzpicture}` или `\begin{asy}…\end{asy}`, либо fenced-блок с языком latex/tikz/asy. Кнопка «Отобразить LaTeX» строит изображение; редактор настроек позволяет проверить код до отправки. Предел источника — 16 000 символов, общий лимит сообщения чата остаётся 4000. Telegram-доставка не изменена: поддержка произвольных рисунков Telegram-клиентом не добавлялась.

## Выполнение и ресурсы

WASM и core dump загружаются только при первом запросе TikZ: около 10,4 МБ плюс JS около 0,46 МБ. Имена бинарных ресурсов содержат hash, для них включён immutable browser cache. Шрифты, которые нужны рисунку, подгружаются с этого же сайта и встраиваются в SVG. Никаких запросов к публичному компилятору/CDN с пользовательским кодом нет.

Worker видит виртуальную файловую систему движка; его fetch ограничен двумя локальными бинарными ресурсами, cookies при загрузке не передаются. Рисунки выполняются последовательно, каждый в новом worker. Ожидание загрузки — до 60 секунд, вычисление — до 20 секунд; worker принудительно завершается, страница остаётся интерактивной. Результат фильтруется по разрешённым SVG-элементам/атрибутам, обработчики событий и внешние ссылки удаляются. SVG отображается только через image context, а не как исполняемая разметка страницы. Кэш последних результатов находится только в памяти текущей страницы.

Исходники/условия TikZJax и BaKoMa, локальные изменения и контрольные суммы находятся в public/vendor/tikzjax/NOTICE.txt, LICENSE.md, fonts/LICENSE.txt и checksums.json. Версии npm и lockfile не изменены. Новая миграция для пакета 021 не нужна; миграция 020 нужна только для сохранения общих библиотек, базовое отображение работает и без её настроек.

## Примеры

```latex
\begin{tikzpicture}
\draw[->] (0,0) -- (3,0) node[right] {$x$};
\draw (0,0) parabola (2,1);
\end{tikzpicture}
```

```latex
\begin{asy}
size(250);
pair A=(0,0), B=(2,1);
draw(A--B,red+Arrow);
draw(circle((1,0),0.5));
label("Привет",(1,1.4));
\end{asy}
```
